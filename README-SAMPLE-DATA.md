# Fitness Power — database-backed sample data

Adds **fictional test records directly to your Neon database**, not the temporary in-memory preview. No changes are made to Team Access, Better Auth users, credentials, existing member records, existing plans, or existing settings.

**Use a Neon development/staging branch or an empty test database**. These records deliberately affect live-mode KPIs, financial reports, and dashboard totals. Do not seed a production gym database.

## Setup (Windows PowerShell)

1. Stop `npm run dev` (`Ctrl+C`). Download/extract the ZIP into the **root** of your current `fitness-power` project, keeping its `scripts` folder.
2. Your `.env.local` must have a working `DATABASE_URL`, and `DEMO_MODE="false"`.
3. Your database schema must already exist (`npm run db:push` completed and tables exist). You do **not** need to run `db:bootstrap` again or install dependencies.
4. Seed:

```powershell
npx tsx scripts/seed-sample.ts
```

5. Start the server:

```powershell
npm run dev
```

Open `/dashboard`, `/members`, `/plans`, `/payments`, `/attendance`, `/lockers`, `/staff`, `/expenses`, `/reports`, and `/activity`. **Team Access is unchanged**. Settings remain whatever you configured; a fallback Settings row is created only if no Settings row exists.

## Included sections

- 6 new `FP Demo - ...` plans (in addition to your existing plans)
- 144 fictional member profiles with a realistic mixture of active, near-expiry, expired, frozen, and inactive memberships
- Membership periods and renewals, plus payments with cash/bKash/Nagad/bank/card, split installments and a few outstanding balances for testing
- Historical attendance plus several today check-ins and open visits (when the local time permits)
- 36 `T-01` to `T-36` test lockers: occupied, available, under maintenance, and released history
- 12 fictional staff records (these are **not** user accounts)
- 84 sample expense transactions across 7 months, including rent, salaries, equipment, utilities and more
- 72 sample audit log entries, displayed with System rather than impersonating a real administrator
- Dashboard and Reports automatically derive charts and totals from the inserted payments, expenses, memberships, and attendance
- An optional CSV file (`sample-member-import.csv`) containing extra fictional entries to test the **Members → Import CSV** preview/import flow

## Safety and repeatability

- Re-running the seed uses the same IDs and skips duplicates. Existing modified rows are not reset.
- Sample member emails use `fp.sample.member...@example.com` and sample import addresses use `fp.sample.import...@example.com`; `example.com` is a reserved documentation domain, not a customer domain.
- Images and receipt URLs are deliberately blank, so you can test real Cloudinary uploads manually; the seed does not contact Cloudinary.
- No users, passwords, permissions, or authentication credentials are created or changed.
- The optional CSV import does add 10 more member records **only if you manually upload it**. Those are included in cleanup by their reserved sample email pattern.

## Remove the sample data after testing

**Do this only on your development database.** This permanently removes seeded members, their associated payments/check-ins/membership history, sample lockers and assignments, sample plans, sample staff, sample expenses, and the artificial audit records. It also removes test-CSV-imported members using the sample email pattern and the transactions you created for those sample members during testing.

```powershell
npx tsx scripts/seed-sample.ts --clean --yes-delete-sample-data
```

The cleanup refuses to proceed if real members reference a sample plan or have sample locker history. It does not delete Team Access accounts or overwrite your settings. Audit log entries generated by your actual logged-in test actions remain for accountability; only artificial audit log entries created by this script are removed.

If you want to add npm shortcuts **without replacing your package.json**, run once:

```powershell
npm pkg set "scripts.db:seed:sample=tsx scripts/seed-sample.ts" "scripts.db:seed:sample:clean=tsx scripts/seed-sample.ts --clean"
```

Then `npm run db:seed:sample` seeds, and `npm run db:seed:sample:clean -- --yes-delete-sample-data` cleans.

### Important

The script has not been run against your private Neon database and does not need your credentials in chat. If you receive a database error, check the first error after `Sample seed failed:`; do not paste your full `.env.local` or database URL into chat.
